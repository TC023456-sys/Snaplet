## 查看与删除复制缓存

打开 macshot 的「设置 → 捕获 → 输出」，查看「Finder 复制文件夹」下的完整路径。路径可以选中复制，点击「在 Finder 中打开」即可查看、删除其中不需要的 PNG。此路径与普通截图的「保存文件夹」独立。删除当前复制的 PNG 后，Finder 无法继续粘贴它，需要重新复制。软件不会自动删除缓存。

## 安装

下载 `MacShot-Finder.zip`，解压后将 `Snaplet.app` 放入「应用程序」。这是 macshot 的替代版本，使用相同的设置和应用标识。安装前退出并移走原版。首次启动或更换签名后可能需要重新授予屏幕录制权限。

公开构建使用 ad-hoc 签名，未经 Apple 公证。如 macOS 阻止打开，请在系统设置的「隐私与安全性」中确认来源后允许打开。此修改版的「检查更新」和「自动检查更新」只读取 TC023456-sys/Snaplet 仓库中带有 macshot-v 前缀和 MacShot-Finder.zip 安装包的发布版本，忽略 Retina Dummy 发布。发现新版后提示打开对应下载页，由用户下载并安装，不静默替换应用。自动检查默认至多每天一次，设置中的开关可以关闭；测试版开关仅接受此 macshot 分支的测试版。设置里显示更新来源。网络故障不会把 Retina Dummy 当作更新。

## 待机内存优化

关闭设置窗口后释放设置控制器及全部标签页，下次打开保留最后查看的标签页。截图结束或启动预热后闲置 30 秒，释放隐藏的截图面板、工具栏和图形表面；下一次截图按需重建。系统出现内存压力时也会释放闲置面板。正在截图、录制时不释放面板，不删除历史或 Finder 复制文件。实际内存数值取决于屏幕分辨率、历史预览、打开的编辑器和 macOS 内存缓存；不承诺固定占用。

## 授权处理修复

启动不再根据 CGPreflightScreenCaptureAccess 的否定结果自动弹出授权引导。截图快捷键与 URL 均先尝试实际 ScreenCaptureKit 截图；实际失败时才显示引导。未获授权时打开设置或菜单不会后台预热并请求截图权限。引导中的「继续」始终可用，避免预检状态未刷新时卡在窗口里。未经授权时禁用旧 API 的降级截图，避免把桌面壁纸误认为完整截图。

此修改不会绕过系统授权，也不能使 ad-hoc 签名在更新后自动继承旧授权；安装当前版后可能仍需重新登记一次权限。长期保留跨版本授权需要固定的正式签名证书。

## 设置排版修复

通用设置的主题控件与其余控件统一对齐；说明文字与缓存路径受窗口宽度约束，自动换行，不再超出右侧边界。

## 实现及测试

- `FinderClipboard.swift` 创建权限为 0600 的 PNG，剪贴板通过 AppKit 的 NSURL 写入机制提供文件引用。
- 在后台编码和写文件；原有剪贴板世代和 changeCount 检查避免慢任务覆盖用户后来复制的内容。过期任务的临时文件会被删除。
- 文件写入失败时仍可复制图片内容。
- 文件保存在 macshot 沙盒缓存的 `FinderClipboard` 子目录中。已复制的文件不会在退出时删除，以便退出后仍可粘贴；这些文件可能包含敏感截图，可在不再需要粘贴时手动清理此缓存目录。
- 独立测试验证 PNG 文件内容、图片读取、文件 URL 读取和无文件时的退化行为。云端另外执行上游单元测试和完整 Release 构建。
- Finder/微信端到端行为需要下载后的实际使用验证，不把剪贴板接口测试视为端到端验证。

## 从源码构建

需要完整 Xcode 26。克隆上游固定提交，依次应用 `finder-paste.patch`、`maintainer-attribution.patch`，运行 `python3 brand-snaplet.py <source>`，将 `FinderClipboard.swift` 和 `ForkUpdateService.swift` 放到 `macshot/Services/`。按工作流编译并强制链接 `keyboard/EscapeFix.m` 的通用静态库，再构建 `macshot` scheme。Swift 模块和内部可执行文件保留 macshot 名称；外部应用包改名 Snaplet.app。自动流程见仓库根目录 `.github/workflows/macshot-finder.yml`。Release 附带完整修改后源码，以及 `SnapletFork` 目录内的品牌脚本、图标、键盘代码、测试和补丁。
